# Polio Lab | نظام إدارة المعمل المرجعي لتشخيص شلل الأطفال

نظام كامل (Full-Stack) لإدارة وطباعة استمارات المعمل المرجعي لتشخيص شلل الأطفال والفيروسات المعوية (L20B) بمعايير WHO / VACSERA، مبني بواجهة عربية RTL، وخادم Python، وقاعدة بيانات SQL.

## المزايا

### الاستمارات المعملية (L20B)
- استمارة تشخيص مطابقة لنموذج WHO / VACSERA: ترويسة (شعار منظمة الصحة العالمية + شعار فاكسيرا)، جدول بيانات المريض، قسم نتائج العينتين، وكتلة التوقيع والختم.
- إنشاء وتعديل وحذف الاستمارات مع تحقق من الحقول (الرقم القومي حروف وأرقام دون تقييد بعدد الخانات، الرقم المعملي فريد، التواريخ، نتائج L20B).
- رفع صورتي الختم والتوقيع (Pillow)، مع ضبط ظهورهما عند الطباعة وموقعهما (يسار / وسط / يمين).
- طباعة مباشرة بمقاس **A4 أفقي** عبر `@media print`: تُخفى عناصر الواجهة وتُطبع الورقة فقط، وتُحوَّل تواريخ `dd/mm/yyyy`.
- سجل الاستمارات مع بحث وتصفية بالمحافظة والنتيجة النهائية، وبطاقات ملخص (إجمالي / نتائج نهائية / قيد الإنجاز / إيجابية).
- يُسجَّل تلقائيًا اسم المستخدم الذي أنشأ كل استمارة ويظهر في عمود «المستخدم» بالسجل، ولا يتغيّر عند تعديل الاستمارة من حساب آخر. الاستمارات القديمة تظهر باسم «غير معروف».
- نظام مراجعة منفصل عن الاستمارة: صفحة «مراجعة الاستمارات» تعرض حالة كل استمارة، وتتيح تسجيل **المراجعة الأولى** و**المراجعة الثانية** مع اسم المراجع وتاريخ ووقت كل مرحلة وربطها بالاستمارة عبر معرّفها.
- رفع ملفات **PDF مجمعة** للاستمارات التي تمت مراجعتها دفعة واحدة: يحلّل النظام الملف تلقائيًا، ويطابق الرقم المعملي أو الرقم القومي، ويطبق المراجعة فقط على الاستمارات الموجودة في الملف. يمكن تضييق النطاق بتحديد مجموعة من نتائج المطابقة.
- تُحفظ بيانات المراجعات في جدول مستقل (مراجعة واحدة لكل استمارة بمرحلتين) مع إنشاء مجلد تلقائي باسم التاريخ ثم رقم الاستمارة، وملف `review.json` يحتوي بيانات المرحلتين ومسار ملف PDF.
- **انتقال تلقائي إلى قسم التسليم**: عند اكتمال المراجعتين الأولى والثانية لأي استمارة، يُضاف مؤشر زمني `delivery_queued_at` تلقائيًا وتنتقل الاستمارة إلى قائمة «الاستمارات الجاهزة للتسليم». يُزال المؤشر إذا أُلغيت المراجعة الثانية لاحقاً.
- **إنشاء PDF مجمع تلقائي**: يُنشئ النظام تلقائيًا ملف PDF واحد يضم جميع الاستمارات الجاهزة للتسليم عبر متصفح Microsoft Edge أو Chrome بوضع headless، مع تحديث الملف عند أي تغيير في المراجعات. يمكن تنزيل الملف أو عرضه من صفحة التسليم، أو إعادة توليده يدوياً.
- تسليم إلكتروني للاستمارات المكتملة المراجعة إلى نظام **EBI** عبر API، مع بيانات المستلم وتاريخ التسليم واسم من سلّمها، وتوثيق تلقائي لوقت العملية، وسجل للاستجابات والأخطاء. القسم متاح لدور المدير فقط.
- طباعة سريعة من السجل عبر `?print=1`.
- صفحة تسجيل دخول عربية متجاوبة، مع جلسات محمية وتحقّق من كلمة المرور على الخادم.
- إدارة المستخدمين من الشريط الجانبي: عرض الحسابات في جدول، إضافة مستخدم جديد، تعديل كلمة المرور، وحذف الحسابات (مع منع حذف الحساب الحالي).
- نظام أدوار: دور **مدير** (`admin`) يرى خيارات إدارة المستخدمين ويستطيع الوصول إليها، ودور **مستخدم** (`user`) يقتصر على الاستمارات المعملية والمراجعات ولا تظهر له خيارات الإدارة.

### تهيئة ملف PDF المجمع التلقائي

يُنشئ النظام تلقائياً ملف PDF مجمع للاستمارات الجاهزة للتسليم باستخدام متصفح Microsoft Edge أو Chrome في وضع headless. يُحدّث الملف تلقائياً بعد كل عملية مراجعة أو عند الدخول إلى صفحة التسليم.

```powershell
# اختياري: مسار مخصص لتخزين ملف PDF المجمع (الافتراضي: data/deliveries)
$env:DELIVERY_PDF_DIR = "D:\polio_pdfs"

# اختياري: تعطيل توليد PDF التلقائي (الافتراضي: مفعّل)
$env:DELIVERY_PDF_ENABLED = "False"

# اختياري: مسار متصفح محدد (الافتراضي: البحث تلقائياً عن Edge ثم Chrome)
$env:DELIVERY_PDF_BROWSER = "C:\Program Files\Google\Chrome\Application\chrome.exe"

# اختياري: مهلة توليد PDF بالثواني (الافتراضي: 30)
$env:DELIVERY_PDF_TIMEOUT = "45"

python app.py
```

**متطلبات النظام:**
- يجب توفر Microsoft Edge أو Google Chrome على الخادم.
- يبحث النظام تلقائياً في المجلدات الشائعة: `Program Files`, `Program Files (x86)`, `LocalAppData`.
- إذا فشل توليد PDF، يُسجَّل الخطأ ولا تتأثر عملية المراجعة أو التسليم.
- في وضع الاختبار (`TESTING=True`)، يُعطّل توليد PDF تلقائياً ما لم يُضبط `DELIVERY_PDF_ENABLED=True` صراحةً.

**الواجهات:**
- `GET /deliveries/pdf`: عرض أو تنزيل ملف PDF المجمع (إضافة `?download=1` للتنزيل المباشر).
- `POST /deliveries/pdf/regenerate`: إعادة توليد ملف PDF يدوياً (مدير فقط).

يُخزَّن الملف الحالي مع بياناته في `data/deliveries/current.json`، ويحتوي على عدد الاستمارات، معرّفاتها، توقيع المحتوى، تاريخ التوليد، واسم ملف PDF. يُحدّث الملف تلقائياً عند تغيّر المراجعات أو القوالب أو ملفات CSS، ويُحذف إذا لم تتبق استمارات جاهزة.

### تهيئة التسليم إلى EBI

يتطلب الإرسال الفعلي ضبط عنوان واجهة EBI وبيانات الاعتماد في بيئة الخادم:

```powershell
$env:EBI_API_URL = "https://ebi.example.org/api/forms/deliveries"
$env:EBI_API_TOKEN = "رمز-الوصول"
# أو استخدم مفتاح API بدلاً من الرمز:
# $env:EBI_API_KEY = "مفتاح-API"
$env:EBI_API_TIMEOUT = "20"
python app.py
```

- يُرسل النظام طلب `POST` بصيغة JSON إلى `EBI_API_URL`.
- عند ضبط `EBI_API_TOKEN` يُرسل كـ`Authorization: Bearer <token>`، وعند ضبط `EBI_API_KEY` يُرسل كـ`X-API-Key`.
- أي استجابة HTTP من فئة `2xx` تُعد نجاحاً؛ غير ذلك يُسجَّل الطلب كفاشل مع رمز الاستجابة ونصها.
- لا تُخزَّن بيانات الاعتماد في قاعدة البيانات أو سجل التسليم.

## تسجيل الدخول

صفحة الدخول متاحة على `/login`، وتحمي صفحات `/forms` و`/reviews` و`/users` وواجهات `/api/forms` التالية:

```powershell
$env:AUTH_USERNAME = "admin"
$env:AUTH_PASSWORD = "كلمة-مرور-قوية"
$env:SECRET_KEY = "مفتاح-عشوائي-طويل-للجلسات"
python app.py
```

- بيانات الدخول الافتراضية للتطوير: `admin` / `polio1234` بدور **مدير**. **غيّرها قبل أي استخدام فعلي.**
- تُخزَّن كلمات المرور مشفّرة (Werkzeug) في جدول `users`، وتُقارَن عبر `check_password_hash`، ولا تُحفَظ كنص صريح.
- يُنشأ حساب المدير من `AUTH_USERNAME` و`AUTH_PASSWORD` عند أول تشغيل فقط (عندما يكون جدول المستخدمين فارغاً)، ويُرقّى الحساب المطابق لـ`AUTH_USERNAME` إلى دور `admin` تلقائياً عند التشغيل. بعد ذلك تُدار الحسابات من صفحة المستخدمين.
- تُحفَظ الجلسة في كوكي موقّع باستخدام `SECRET_KEY`؛ يجب ضبطه بقيمة عشوائية في الإنتاج.
- `/api/health` وملفات الصور والشعارات تبقى متاحة دون تسجيل دخول.

### الأدوار والصلاحيات

| الدور | القيمة المخزّنة | الصلاحيات |
| --- | --- | --- |
| مدير | `admin` | الاستمارات + التسليم إلى EBI + عرض وإدارة المستخدمين (إضافة، تعديل كلمات المرور، حذف) |
| مستخدم | `user` | الاستمارات المعملية والمراجعات فقط |

- خيارات **إدارة المستخدمين** و**إضافة مستخدم** و**تسليم إلى EBI** لا تظهر في الشريط الجانبي إلا لدور `admin`.
- صفحات `/users` و`/users/new` و`/users/<id>/password` و`/users/<id>/delete` وصفحات `/deliveries` محمية على الخادم؛ محاولة وصول مستخدم عادي إليها تُرجع صفحة **403**.
- المستخدمون الجدد يُنشأون بدور `user` افتراضياً، ويمكن للمدير اختيار دور `admin` من نموذج **إضافة مستخدم**.
- قواعد البيانات القديمة تُضاف إليها خانة `role` تلقائياً، ويُرقّى حساب `AUTH_USERNAME` الحالي إلى `admin` عند التشغيل.

لإضافة مستخدم جديد: من الشريط الجانبي اضغط **إضافة مستخدم** (أو افتح `/users/new`)، أدخل اسم المستخدم وكلمة المرور (8 أحرف على الأقل) وأكّدها، واختر الدور، ثم اضغط **إنشاء المستخدم**. يمكن للحساب الجديد تسجيل الدخول مباشرة.

لإدارة الحسابات (لدور المدير): افتح **إدارة المستخدمين** من الشريط الجانبي (أو `/users`) لعرض جميع الحسابات في جدول مع الدور وتاريخ الإنشاء.

- **تعديل كلمة المرور:** يفتح صفحة إعادة تعيين الحساب المحدد دون الحاجة إلى كلمة المرور القديمة، ويطبق كلمة المرور الجديدة فوراً.
- **حذف:** يحذف الحساب بعد تأكيد المتصفح. لا يمكن حذف الحساب المستخدم حالياً، ويُمنع حذف الحساب الأخير تلقائياً بهذه القاعدة.
- **إضافة مستخدم:** متاحة أيضاً من أعلى جدول المستخدمين.

### كيف تُرسَل بيانات الدخول إلى الخادم؟

1. بدون JavaScript: النموذج يُرسل `POST /login` بصيغة `application/x-www-form-urlencoded` (الحقول `username` و`password` و`next`)، ثم يتحقق الخادم ويعيد التوجيه إلى `/forms` أو يعرض الخطأ.
2. مع JavaScript: يعترض `static/js/login.js` الإرسال ويرسل طلب JSON:

```javascript
fetch("/api/login", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    credentials: "same-origin",
    body: JSON.stringify({ username, password, next }),
});
```

يستجيب الخادم بـ `{"ok": true, "redirect": "/forms"}` عند النجاح، أو `401` مع `{"error": "..."}` عند الخطأ. يتم التحقق دائمًا على الخادم، والتحقق في المتصفح للراحة فقط.

| POST | `/deliveries` | إرسال الاستمارات المحددة إلى EBI وتسجيل بيانات التسليم (مدير فقط) |
| GET | `/deliveries/<id>` | تفاصيل عملية تسليم واستجابة EBI (مدير فقط) |
| GET | `/deliveries/pdf` | عرض أو تنزيل ملف PDF المجمع للاستمارات الجاهزة (مدير فقط) |
| POST | `/deliveries/pdf/regenerate` | إعادة توليد ملف PDF المجمع يدوياً (مدير فقط) |
| GET | `/uploads/<filename>` | تقديم صورة الختم أو التوقيع المخزّنة |
| GET | `/api/health` | فحص جاهزية الخدمة |

يقبل `/api/forms` بحقلَي `stamp_image` و `signature_image` إمّا رابط ملف مخزّن أو `data:image/...;base64,...` مباشرة من المتصفح، ويتم تخزين الصورة بعد التحقق وتصغيرها (الضلع الأطول ≤ 1400 بكسل).

يعيد إنشاء الاستمارة وقائمة `/api/forms` الحقل `created_by` باسم المستخدم الذي أنشأها. يُضبط هذا الحقل تلقائيًا من الجلسة عند الإنشاء فقط، ولا يمكن تغييره عبر طلب التحديث.

بيانات المراجعة منفصلة عن `/api/forms`: تُسجَّل المراجعة الأولى والثانية من صفحة `/reviews/<form_id>` أو من `/reviews/batch` عند رفع ملف PDF مجمع. تُخزَّن في جدول `form_reviews` المرتبط بالاستمارة عبر `lab_form_id`، مع أعمدة مستقلة لاسم وتاريخ ووقت كل مرحلة ومسار `pdf_path` وعمود `delivery_queued_at` الذي يُملأ تلقائياً عند اكتمال المرحلتين. يجب إدخال اسم المراجع مع تاريخ ووقت بصيغة `YYYY-MM-DDTHH:MM`، وتُرفض الصيغة غير الصحيحة أو وقت المراجعة المستقبلي. عند الرفع المجمع يحلّل النظام ملف PDF دائماً ويستخرج الرقم المعملي أو الرقم القومي، ثم يحدد الاستمارات المطابقة. النطاق الافتراضي «جميع الاستمارات المطابقة في ملف PDF» ويطبق اسم المراجع وتاريخ ووقت المراجعة على كل المطابقات. يمكن اختيار «تحديد مجموعة من نتائج ملف PDF» لتضييق التطبيق على مجموعة مختارة، لكن لا يمكن تطبيق المراجعة على استمارة غير موجودة في الملف؛ وإذا لم يوجد أي تطابق يُرفض الملف. تحديد استمارة واحدة يوسّع التحديد إلى جميع الاستمارات ثم يحصره النظام في المطابقات. يجب أن يكون ملف PDF نصيًا وقابلًا لاستخراج النص، ويُقبل ملف PDF صالح فقط بحد أقصى 30 ميجابايت. يُنشأ لكل استمارة مجلد `data/reviews/YYYY-MM-DD/form-<form_id>/` يحتوي ملف `review.json`، ويُخزَّن الملف المجمع في `data/reviews/pdfs/YYYY-MM-DD/`.

عند اكتمال المراجعتين الأولى والثانية، يُضاف الطابع الزمني `delivery_queued_at` تلقائياً، وتنتقل الاستمارة إلى قائمة الاستمارات الجاهزة في صفحة `/deliveries`، ويُنشأ أو يُحدّث ملف PDF المجمع تلقائياً. إذا أُلغيت المراجعة الثانية لاحقاً، يُمسح مؤشر `delivery_queued_at` وتُزال الاستمارة من قائمة التسليم ويُحدّث ملف PDF المجمع.

### التسليم إلى EBI

صفحة `/deliveries` متاحة لدور `admin` فقط. تعرض الاستمارات المؤهلة للتسليم، وهي الاستمارات التي اكتملت لها المراجعة الأولى والثانية ولم تُسلَّم بنجاح من قبل. تنتقل الاستمارات إلى هذه القائمة تلقائياً بمجرد حفظ المراجعة الثانية. كما تعرض الصفحة بطاقة ملف PDF المجمع الذي يضم جميع الاستمارات الجاهزة بصيغة قابلة للطباعة أو التنزيل، ويُحدّث تلقائياً عند كل تغيير. بعد اختيار الاستمارات وإدخال اسم المستلم وجهته وبيانات الاتصال وتفاصيله، وتاريخ التسليم، واسم الشخص الذي سلّمها، يُنشئ النظام مرجعاً للتسليم مثل `EBI-20261022170000-A1B2C3` ويحفظ وقت العملية تلقائياً في `created_at`، ثم يرسل طلب JSON إلى `EBI_API_URL`.

تُحفظ كل محاولة في الجدولين `ebi_deliveries` و`ebi_delivery_forms`، بما يشمل بيانات المستلم، ومن سلّم الاستمارات، وحالة الطلب (`pending` أو `delivered` أو `failed`)، ورمز استجابة HTTP ونصها، ونص البيانات المرسلة. لا تُعد الاستمارة مسلّمة إلا عند نجاح العملية؛ لذلك يمكن إعادة المحاولة بعد الفشل. تظهر الاستجابات الكاملة في صفحة `/deliveries/<id>`.

## ملاحظات الأمان

- جميع الاستعلامات تستخدم معلمات SQL لمنع الحقن.
- التحقق من المدخلات يتم على الخادم قبل الحفظ.
- كلمات المرور تُقارَن عبر Hash، والجلسات موقّعة، وروابط العودة (`next`) محمية من إعادة التوجيه المفتوح.
- صفحات الإدارة والـ API تتطلب تسجيل دخول، مع استثناء فحص الصحة والملفات العامة.
- إدارة المستخدمين (العرض، الإنشاء، تعديل كلمة المرور، الحذف) متاحة لدور `admin` فقط، ويُتحقق من الدور على الخادم في كل مسار، وتُخزَّن كلمات المرور الجديدة مشفّرة في جدول `users`.
- إخفاء روابط الإدارة في الشريط الجانبي إجراء واجهة فقط؛ الحماية الفعلية مطبقة عبر `admin_required` وتُرجع `403` للمستخدمين العاديين.
- الحذف يتم عبر `POST` مع تأكيد في الواجهة، ويُرفض حذف الحساب الحالي على مستوى الخادم.
- يتم تعقيم النصوص المعروضة في الواجهة لمنع XSS.
- رفع الصور مقيّد بنوع `image/*` والحجم، ويتم التحقق من محتوى الملف عبر Pillow قبل التخزين.
- ملفات المراجعة PDF تُتحقق من امتدادها وتوقيعها وحجمها، ويُقرأ نصها عبر `pdfminer.six` لمطابقة الاستمارات، وتُقدَّم عبر مسار محمي يمنع الخروج من مجلد المراجعات.
- مسارات ملفات الرفع محمية من الاقتحام عبر التحقق من اسم الملف و`send_from_directory`.
